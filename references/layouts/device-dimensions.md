## 断点间距

各栏内部 padding 根据该栏自身宽度（w）按以下断点判定。应用全屏、分屏、小窗共用同一套规则。

> **自带内部 padding 的组件一律栏内风满（全设备通用）**: 下列组件实例 **本身已内置左右 padding**，在栏内必须以 `x = 0, width = 栏W` 风满放置，**不得再叠加栏断点 padding**（否则内容会被 double-inset）：
>
> - `NavigationBar` / `NavigationBar_ComponentSet_Notes`（内置 `左12；右12`）
> - `SearchBar_ComponentSet`（内置 `左12；右12`）
> - `SelectableChip_ComponentSet_*`（内置 `左12`）
> - `List_Notes` / 各应用列表（内置 `左12；右12`）
> - `Detail_Notes` / 各应用详情容器
> - `TextInput_ComponentSet_Notes`
> - `BottomBar_Showcase_*` / `ToolBar_*`（渐变遮罩栏风满，内部胶囊按工具栏规格单独处理）
> - `Sidebar_Component_*`（外壳栏风满，内部卡片/菜单自带偏移）
>
> 下方「断点间距」表仅适用于 **无自带 padding 的裸控件 / 业务容器** （如纯 Frame、分组卡片外框等）。具体应用的组件若其 `app-variant-map-*.md` 的「组件间距」表记录与本规则冲突，**以 `device-dimensions.md` 为准**，组件间距表按此修正。

> **Q18 特例（OS4 新增）**：Q18 设备（Fold 内屏）在 **容器宽度 w ≤ 640dp** 区间统一使用 **12dp** padding，不再按 420 / 640 细分。仅当 Q18 内屏 **横屏 C 栏通栏** 且 `800 ≤ w ≤ 1100` 时使用 56dp。各 Fold 章节的 padding 表已按此特例给出具体值；下表的 20dp / 28dp 仅适用于 **非 Q18** 设备（如 Pad）。

| 断点 | 间距（左右 padding） |
|------|-----------------|
| w ≤ 420 | 12dp |
| 420 < w ≤ 640 | 20dp |
| 640 < w ≤ 800 | 28dp |
| 800 < w ≤ 1100 | 56dp |
| 1100 < w | 56dp + Fill（内容区域 max 988dp，居中展示，两侧边距 Fill） |

> 当容器宽度 > 1100dp 时：内容区域最大宽度 = 988dp（容器 1100 − 左侧间距 56 − 右侧间距 56），不再拉伸，居中展示，两侧边距 Fill。

> 所有 N 栏在显示悬浮侧边栏时，N 栏内部左侧会产生 6dp 的 padding（由组件自身携带）。

## 无限集宫格类型（大屏适配）

页面内具有宫格元素，且元素个数为无限集时，为了在大屏上满足浏览需求，屏幕越大，展现个数越多。当大屏内容器宽 > 1100dp 时，内容仍需拉伸，两侧边距固定。

| 维度 | 值 |
|------|-----|
| 两侧边距 | 固定 **28dp**（Fixed） |
| 列间距 | **Fill**（均等分配剩余空间） |

> **注意**：宫格类型的布局边距和断点规则详见「超级宫格」page。
>
> 1. 业务可按设计效果自定义边距（默认这套容器规范可做参考，如有特殊视觉要求即可自定义，业务研发可与 MIUIX 研发先拉通适配方式）
> 2. 此处示例文管业务的大屏变化，仅作参考

## 栏内部结构尺寸

### N 栏侧边栏（NLC / NC 模式）

NLC / NC 模式下的 N 栏为悬浮卡片式侧边栏，内部分层结构如下：

> **例外**：侧边栏外壳直接贴紧状态栏下沿（无 6dp 外部间距），不适用「基本对齐方式」中「栏内容与状态栏之间 6dp padding」的通则。**外壳内部也无 6dp 上偏移**，卡片上沿紧贴外壳上沿，即紧贴状态栏下沿（`卡片 y = 0`）。

| 层级 | 名称 | 宽度 | 说明 |
|------|------|------|------|
| 外壳 | 侧边栏 | 272dp | N 栏总宽度；`paddingTop = 0`, `paddingLeft = 12`, `paddingRight = 0`, `paddingBottom = 12` |
| 卡片 | 板子材质层 | 260dp | 左偏移 12dp（外壳 paddingLeft），上偏移 0dp；带圆角背景 |
| 标题栏 | NavigationAtoms（导航类型=切换顶导航 等） | 260dp | **高 56dp**，位于卡片内顶部 `y = 0` |
| 标题栏 ↔ 内容区域 间距 | — | — | **下 6dp padding**（标题栏底至内容区域顶） |
| 内容 | NavigationSizeSection / 内容区域 | 260dp | 位于标题栏下方 `y = 56 + 6 = 62`，与卡片同宽 |
| 菜单项 | 导航组件_原子 / 菜单内容_原子 | 236dp | 卡片内左偏移 12dp |

> **同步状态（2026-05-14）**：团队已将 `NavigationAtoms` 高度由旧值 44dp 更新为 56dp。若当前文件中 Sidebar 实例仍显示 44dp / `内容区域 y = 60`，表示组件库尚未同步。执行校验时遇到 44dp，应先触发实例刷新（如重新拖入新实例、或等 Figma 同步后 `resetOverrides`），不要手动覆盖实例内部尺寸。

## 基本对齐方式

画面内控件从上到下依次排列。底部导航栏、Fab 等以画面底部为基准对齐。各区域宽度变化时，控件宽度自适应填充。各控件内部自带左右 padding。

Fold 和 Pad 的所有栏内容从状态栏下方开始排列，各栏内容与状态栏之间需要 6dp 的 padding。

| 控件 | 对齐方式 |
|------|---------|
| 状态栏 | 顶部对齐 |
| 顶部导航（标题栏 / 顶部导航栏） | 顶部对齐 |
| 侧边栏 | 左对齐 |
| 搜索栏 | 顶部对齐 |
| 标签栏 | 顶部对齐 |
| 分段按钮 | 顶部对齐 |
| 底部导航栏（BottomBar 系列，含 `_Showcase_*` / `_Fab_*` / `BottomBar_Showcase_Notes_*` 等全部变体） | 底部对齐 |
| Fab | 底部右下角对齐 |
| 输入框 | 底部对齐 |

手机 和 Fold 外屏 均直接使用基本对齐方式。

## 遮罩定义

分栏模式下 N 栏覆盖时，被覆盖栏上方展示遮罩层。

| 属性 | 值 |
|------|-----|
| Token | 遮罩色/mask |
| 色值 | #000000 |
| 透明度 | 20% |

### 适用范围

- **并列 形态**: 无遮罩。
- **覆盖 形态**: 遮罩覆盖目标 frame **整体（含状态栏）**。覆盖组件（Sidebar 等）本身位于遮罩之上，不在遮罩之下。
- **收起态**: 不存在覆盖形态，无遮罩。
- 本范围约束优先级高于各应用 `app-variant-map` 中的局部遮罩描述——任何 "L+C 覆盖遮罩" / "LC 有遮罩" 类表述应统一理解为「整个 frame 遮罩 − 覆盖组件(Sidebar) 自身」。
- 编辑状态遮罩（L/C 进入编辑态等）沿用同一范围原则：覆盖整个 frame，覆盖态下的 Sidebar / 被豁免控件除外；各应用 map 中的 "L + C 栏全部覆盖遮罩" 类旧表述按本条重解。

### N 栏 Sidebar 阴影 z-order（并列 / 覆盖 通用）

N 栏 Sidebar 外壳 `clipsContent = false` 故意允许卡片阴影外溢——**阴影必须渲染在 L / C 栏之上**，使 L 栏左侧边缘能看到 Sidebar 的浅阴影。

执行要求：

- Sidebar 节点在 frame / 父容器的 children 列表中 **放在最后**（top z-order）
- `并列` 模式下若 N 栏也是 `main` horizontal auto-layout 的第一个子节点，会被 L/C 覆盖阴影 → **将 Sidebar 从 N 栏容器中取出，挂到 frame 直接子级（最后位）**，同时 `main` 改为 non-autolayout 并把 L/C 手动定位到 `N 栏宽度` 之后
- `覆盖` 模式已天然满足（Sidebar 本来就在 frame 最上层），无需额外处理

结构示例（Pad 横 NLC 并列）：

```
frame (1422×949, cornerRadius 34)
├─ main (y=34, 1422×915, non-autolayout)
│   ├─ L (x=272, 428×915)
│   └─ C (x=700, 722×915)
├─ 状态栏 (y=0, 1422×34)
└─ Sidebar (y=34, 272×915)   ← 最上层，阴影投射到 L/C 之上
```

### 覆盖 布局实例示范（Pad 竖屏 NLC 展开 — 应用级可选）

> 应用决定是否采用 `覆盖` 模式。默认 `并列`；`覆盖` 须在该应用的 `app-variant-map` 中明确声明。Pad 横屏 NLC / 所有收起态均不支持 `覆盖`。

z-order 与结构（以 Pad 竖屏 949×1422 为例）：

```
frame (949 × 1422, fill = 背景色/surface_low, cornerRadius = 34)
├─ status bar (y = 0,  949 × 34)
├─ main (y = 34, 949 × 1388, non-autolayout)
│   ├─ L (x = 0,   428 × 1388, fill = 背景色/surface_low)   ← 列表卡片承载层
│   └─ C (x = 428, 521 × 1388, fill = 应用判定（笔记 Detail = surface；列表卡片场景 = surface_low）, strokeLeft 1dp 分割线)
├─ 遮罩 (x = 0, y = 0, 949 × 1422, 遮罩色/mask 20%)   ← frame 级，main 的 sibling
└─ Sidebar (x = 0, y = 34, 272 × 1388)                  ← 遮罩之上；外壳贴紧状态栏下沿
```

关键约束：

1. `覆盖` 模式下 L/C 使用 **LC 基准尺寸**（L 428 + C 521），**不使用** NLC 并列尺寸（304 + 373）。
2. 遮罩层放在 frame 级（非 main 内部），宽高等于 frame 整体（含状态栏）。
3. Sidebar 层级高于遮罩。Sidebar 外壳自身直接贴紧状态栏下沿；内部卡片由组件自带 12dp 左 / 6dp 上偏移。
4. 标题栏（NavigationBar_12 等）作为 Sidebar 内部头部存在，**不另行 sibling 放置**（详见 `app-variant-map-template.md`「分号 · 跨表合并解释规则」）。
5. 收起态（N 消失）时不存在此结构，遮罩亦不生成。
6. **栏 padding**: 按本文档最上方「断点间距」表 **由各栏宽度自动决定** —— 与模式（NLC / LC / 覆盖 / 并列）无关。示例（Pad 竖 NLC 覆盖）：
   - N 栏 272dp → `w ≤ 420` → 12dp（由 Sidebar 外壳自带的 12/6 偏移吸收）
   - L 栏 428dp → `420 < w ≤ 640` → 20dp
   - C 栏 521dp → `420 < w ≤ 640` → 20dp

> **全局原则**：「断点间距」表为 master 规则；各版本 padding 表（如「Pad 横屏 - 各栏间距」）仅为 断点表 的具体应用示例，如有冲突以断点表为准。组件自带的 `左12；右12` 为组件内部 content inset，与 栏 padding（栏 edge → 组件 edge）分属两层，不相互抵消。

## 横竖屏旋转规则（Pad / Fold 通用）

NLC 与 NC 框架均适用以下规则：

1. **展开态映射**：横屏展开态 ↔ 竖屏展开态，收起态 ↔ 收起态
2. **独立历史记录**：横竖屏各自记录用户干预后的侧边栏状态
3. **状态循环**：横屏收起 →❶ 竖屏展开 →❷ 竖屏收起 →❸ 横屏展开 →❹ 横屏收起
4. **禁止旋转出模态导航**：旋转不能触发导航模态切换

## 工具栏规格

底部工具栏（ToolBar / BottomBar_Showcase / NoteEditPanel / Notes_Outline 系列）的尺寸、位置、遮罩规则。工具栏为「胶囊 + 遮罩」复合结构；胶囊为实际承载控件的悬浮卡片，遮罩为胶囊周围的自适应视觉层。

### 结构

底部工具栏整体由两层组成：

```
┌─────────────────────────┐ ← 遮罩顶部
│  上 padding 20dp（固定）      │
├─────────────────────────┤
│  胶囊（悬浮层）              │
├─────────────────────────┤
│  下 padding（自适应，最小 24dp）│  ← 容纳控制杆 / 虚拟键 / 底部遮挡
└─────────────────────────┘ ← 遮罩底部 = 屏幕底部 0dp
```

- **遮罩**：可为渐变色遮罩，也可为透明空间，由 App 环境决定。
- **胶囊**：实际承载 tab / 按钮的悬浮卡片。

> **栏内放置规则（关键）**：
> - 工具栏 instance（整体容器）必须以 **`x = 0, width = 栏W`** 放置，即 instance 与其内部 `Overlay-Showcase` 遮罩层共同填满栏宽。
> - 「胶囊尺寸」下文表中的 `栏W − 48` / 定宽 344dp 是 **胶囊层 `TabMaterial-Showcase` 的宽度规则**，不是 instance 外壳宽度。
> - 错误做法：把 instance 整体缩到 `栏W − 48 / x = 24`。这样会连带把渐变遮罩层一起缩小，导致栏两侧露出空白、遮罩不再贴栏边。
> - 正确做法：保持 instance 风满栏宽，胶囊由 instance 内部 layout 自动居中（或按需 override 到 `栏W − 48` 铺满 / `344` 定宽）。

### 胶囊尺寸

#### 常规态

| 维度 | 值 |
|------|-----|
| 高度 | **56dp** |
| 宽度 | 画面宽 ≤ 440dp → **铺满**（画面宽 − 48，左右 24dp padding） |
| | 画面宽 > 440dp → **定宽 344dp**（居中，两侧余量均分） |

#### 缩小态

| 维度 | 值 |
|------|-----|
| 高度 | **44dp** |
| 宽度 | 各 tab 宽度累加（左右横向排列）；单个 tab 最大宽度 **166dp** |

### 遮罩高度（自适应）

遮罩总高 = 上 padding 20 + 胶囊高度 + 下 padding。下 padding 最小 24dp，根据底部元素自适应：

| 场景 | 下 padding | 常规态遮罩总高 |
|------|-----------|---------------|
| 基本（无控制杆 / 无键盘 / 无遮挡） | 24dp（最小） | 20 + 56 + 24 = **100dp** |
| 虚拟键展开（默认键高 48dp） | 8 + 48 = 56dp | 20 + 56 + 56 = **132dp** |
| 底部遮挡 ≤ 24dp（如常规控制杆 16dp） | 24dp（沿用基本） | **100dp** |
| 底部遮挡 > 24dp（如小窗控制杆 X dp） | 8 + X | 20 + 56 + 8 + X = **84 + X dp** |

胶囊与底部元素（控制杆 / 虚拟键 / 遮挡）之间的 padding 固定为 **8dp**；遮罩底部始终贴屏幕底部 0dp。

### 常规态 ↔ 缩小态 切换交互

| # | 触发 | 结果 |
|---|------|------|
| ① | 常规态下上滑页面超过 50% | 缩小态 |
| ② | 滑动中 / 停止滑动 | 保持缩小态（不会因停止自动恢复） |
| ③ | 反向滑动 | 恢复常规态 |
| ④ | 缩小态下点击切换 tab | 恢复常规态 |
| ⑤ | 缩小态下滑动切换 tab | 恢复常规态 |
| ⑥ | 缩小态下左右滑动切换页面 | 恢复常规态 |
| ⑦ | 大小态切换时 | 居中向下切换，距屏幕底部始终 **24dp**，左右 padding 等距 |

### tab 数量

- 默认最多 **5 个**
- App 可按业务特例调整（例如 `BottomBar_NoteEditPanel_01` 为业务特别形态）
